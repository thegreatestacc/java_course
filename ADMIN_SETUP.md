# Настройка админ-панели

## Описание

Админ-панель позволяет просматривать всех зарегистрированных пользователей, блокировать и разблокировать их. Доступ к админке имеют только пользователи с правами администратора (`isAdmin = true`) **и** email которых совпадает с админским email, указанным в настройках `app.admin.email`.

## Настройка

### 1. Указать админ email

В файле `backend/src/main/resources/application.properties` (для разработки) или `backend/src/main/resources/application-prod.properties` (для production) укажите ваш email:

```properties
app.admin.email=ваш-email@example.com
```

Или установите переменную окружения:

```bash
export ADMIN_EMAIL=ваш-email@example.com
```

### 2. Регистрация админа

1. Зарегистрируйтесь в системе, используя email, указанный в настройках
2. При регистрации с этим email автоматически будут назначены права администратора
3. Войдите в систему

### 3. Доступ к админке

После входа в систему как администратор:
- В хедере появится кнопка "Админка"
- Перейдите по адресу `/admin`
- Или используйте прямую ссылку: `http://localhost:3000/admin` (для разработки)

## Функционал админки

- **Просмотр всех пользователей**: список всех зарегистрированных пользователей с информацией:
  - ID
  - Email
  - Имя
  - Дата регистрации
  - Статус (Активен/Заблокирован)
  - Роль (Админ/Обычный пользователь)

- **Блокировка пользователей**: 
  - Нажмите кнопку "Заблокировать" рядом с пользователем
  - Заблокированный пользователь не сможет войти в систему

- **Разблокировка пользователей**:
  - Нажмите кнопку "Разблокировать" рядом с заблокированным пользователем
  - Пользователь снова сможет войти в систему

## Безопасность

1. **Проверка прав доступа**: 
   - Все endpoints админки проверяют, что пользователь авторизован, имеет права администратора (`isAdmin = true`) **И** его email совпадает с админским email из настроек (`app.admin.email`)
   - Доступ к админке имеют только пользователи с указанным в настройках email
   - Если пользователь не соответствует этим требованиям, доступ к админке запрещен

2. **Защита от блокировки себя**:
   - Администратор не может заблокировать сам себя

3. **Проверка блокировки при входе**:
   - Заблокированные пользователи не могут войти в систему
   - При попытке входа они получат сообщение о блокировке

4. **Ограничение доступа по email**:
   - Даже если у пользователя установлен флаг `isAdmin = true`, доступ к админке будет разрешен только если его email совпадает с `app.admin.email` из настроек
   - Это обеспечивает дополнительный уровень безопасности

## API Endpoints

- `GET /api/admin/users` - Получить список всех пользователей (только для админов)
- `POST /api/admin/users/{userId}/block` - Заблокировать пользователя (только для админов)
- `POST /api/admin/users/{userId}/unblock` - Разблокировать пользователя (только для админов)

## Важные замечания

1. **Первый админ**: Если вы уже зарегистрированы, но не являетесь админом, вам нужно:
   - Зарегистрировать новый аккаунт с админским email (указанным в `app.admin.email`)
   - При регистрации с этим email автоматически установится `is_admin = true`
   - **Важно**: Доступ к админке будет только у пользователя с email, совпадающим с `app.admin.email`

2. **Изменение админ email**: Если вы хотите изменить админ email:
   - Обновите настройку `app.admin.email` в `application.properties` или `application-prod.properties`
   - Перезапустите приложение
   - Новые пользователи с этим email автоматически получат права администратора при регистрации
   - **Важно**: Доступ к админке будет только у пользователя с новым email из настроек

3. **Production**: В production используйте переменную окружения `ADMIN_EMAIL` для безопасности

4. **Миграции базы данных**: Проект использует Liquibase для управления миграциями. Поля `is_admin` и `is_blocked` автоматически добавляются при первом запуске приложения.
