# Устранение проблемы SSH подключения с клиента

## Ситуация
- **Сервер:** SSH работает, порт 22 открыт, слушает на 0.0.0.0:22
- **Клиент:** Не может подключиться, ping не проходит

## Возможные причины

### 1. Провайдер клиента блокирует исходящие соединения

Некоторые провайдеры/корпоративные сети блокируют исходящие SSH соединения.

**Решение:**
- Попробуйте с другого интернета (мобильный интернет, другая сеть)
- Используйте VPN
- Попробуйте с другого компьютера

### 2. Windows Firewall блокирует

**Проверка:**
```powershell
# Проверить правила файрвола
Get-NetFirewallRule | Where-Object {$_.DisplayName -like "*SSH*"}

# Временно отключить файрвол для теста (НЕ рекомендуется для продакшена)
Set-NetFirewallProfile -Profile Domain,Public,Private -Enabled False
```

### 3. Антивирус блокирует

Проверьте настройки антивируса - некоторые блокируют SSH соединения.

### 4. Проблема с DNS/маршрутизацией

**Проверка:**
```powershell
# Проверка маршрута
tracert 5.129.200.192

# Проверка DNS
nslookup 5.129.200.192
```

### 5. Провайдер сервера блокирует ваш IP

Возможно, провайдер сервера блокирует ваш IP адрес из-за предыдущих попыток подключения.

**Решение:**
- Попробуйте с другого IP (другой интернет)
- Обратитесь в поддержку хостинга

## Альтернативные способы подключения

### Вариант 1: Использовать веб-консоль хостинга

Если у вас есть доступ к панели управления, используйте веб-консоль для работы на сервере.

### Вариант 2: Использовать другой порт

Если порт 22 блокируется, можно изменить порт SSH на сервере:

```bash
# На сервере
sudo nano /etc/ssh/sshd_config
# Измените:
Port 2222

sudo systemctl restart sshd
sudo ufw allow 2222/tcp
```

Затем подключайтесь:
```bash
ssh -p 2222 root@5.129.200.192
```

### Вариант 3: Использовать VPN

Подключитесь через VPN и попробуйте снова.

### Вариант 4: Использовать другой компьютер/сеть

Попробуйте подключиться с другого компьютера или через мобильный интернет.

## Проверка с сервера

Попробуйте подключиться С СЕРВЕРА к другому серверу, чтобы убедиться, что исходящие соединения работают:

```bash
# На вашем сервере
ssh -v root@5.129.200.192
```

## Временное решение для GitHub Actions

Если локальное подключение не работает, но GitHub Actions должен работать, проверьте:

1. **GitHub Actions использует другие IP адреса** - возможно, они не заблокированы
2. **Попробуйте запустить workflow** - возможно, он сработает, даже если локальное подключение не работает

Введите IP `5.129.200.192` и порт `22`.
