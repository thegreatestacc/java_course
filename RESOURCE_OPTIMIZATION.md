# Оптимизация использования ресурсов сервера

Этот документ описывает оптимизации, внесенные для эффективного использования ограниченных ресурсов сервера (1 CPU, 1 ГБ RAM, 15 ГБ NVMe).

## Внесенные оптимизации

### 1. Redis для кэширования и сессий

**Что сделано:**
- Добавлен Redis контейнер в `docker-compose.prod.yml` с ограничениями: 128MB памяти, 0.2 CPU
- Настроен Redis для хранения сессий пользователей (через Spring Session)
- Реализовано кэширование часто запрашиваемых данных в Redis

**Преимущества:**
- Снижение нагрузки на PostgreSQL (меньше запросов к БД)
- Быстрый доступ к кэшированным данным
- Централизованное хранение сессий (позволяет масштабировать backend)

**Настройки Redis:**
- Максимальная память: 128MB
- Политика удаления: `allkeys-lru` (удаление наименее используемых ключей)
- Отключено persistence (экономия диска и производительности)

### 2. Кэширование данных

**Кэшируются следующие данные:**

#### Статистика пользователя (`userStatistics`)
- TTL: 10 минут
- Кэшируется результат `getUserStatistics()`
- Инвалидируется при изменении прогресса материалов

#### Активность пользователя (`userActivity`)
- TTL: 15 минут
- Кэшируется результат `getUserActivity()` и `getUserActivityByYear()`
- Инвалидируется при записи новой активности

#### Статус материала (`materialStatus`)
- TTL: 5 минут
- Кэшируется результат проверки завершенности материала
- Инвалидируется при изменении статуса материала

#### Результаты компиляции (`compileResults`)
- TTL: 1 час
- Кэшируются только успешные результаты компиляции и выполнения
- Ключ: хэш кода
- Значительно снижает нагрузку на CPU при повторных компиляциях одинакового кода

**Реализация:**
- Используется Spring Cache с Redis
- Автоматическая инвалидация кэша при изменении данных
- Не кэшируются null значения (экономия памяти)

### 3. Rate Limiting для компиляции

**Что сделано:**
- Реализован `RateLimitService` для ограничения частоты запросов на компиляцию
- Лимит: 10 запросов в минуту на пользователя/IP
- Использует Redis для хранения счетчиков

**Преимущества:**
- Защита от злоупотребления ресурсоемким эндпоинтом компиляции
- Справедливое распределение ресурсов между пользователями
- Предотвращение перегрузки CPU

### 4. Оптимизация пула соединений с БД

**Текущие настройки (уже были):**
- Максимум 5 соединений (вместо 10 по умолчанию)
- Минимум 2 idle соединения
- Настроены таймауты для предотвращения утечек

**Экономия:**
- Меньше памяти на пул соединений
- Меньше нагрузки на PostgreSQL

### 5. Оптимизация JVM

**Текущие настройки (уже были):**
- `-Xmx512m` - максимум 512MB heap памяти
- `-Xms256m` - начальная heap память 256MB
- `-XX:+UseG1GC` - G1 garbage collector
- `-XX:MaxGCPauseMillis=200` - максимальная пауза GC 200ms
- `-XX:MaxRAMPercentage=75.0` - использовать максимум 75% доступной памяти

### 6. Оптимизация Redis

**Настройки Redis контейнера:**
```yaml
command: redis-server --maxmemory 128mb --maxmemory-policy allkeys-lru --save "" --appendonly no
```

- `maxmemory 128mb` - ограничение памяти
- `maxmemory-policy allkeys-lru` - удаление наименее используемых ключей при нехватке памяти
- `save ""` - отключение persistence (экономия диска и производительности)
- `appendonly no` - отключение AOF (экономия диска)

## Распределение ресурсов

### Docker Compose ресурсы:

| Сервис | CPU Limit | Memory Limit | CPU Reservation | Memory Reservation |
|--------|-----------|--------------|-----------------|-------------------|
| PostgreSQL | 0.5 | 512MB | 0.25 | 256MB |
| Backend | 0.7 | 768MB | 0.3 | 384MB |
| Redis | 0.2 | 128MB | 0.1 | 64MB |
| Nginx | 0.3 | 128MB | 0.1 | 64MB |
| Frontend | 0.4 | 512MB | 0.2 | 256MB |
| **Итого** | **2.1** | **~2GB** | **0.95** | **~1GB** |

**Примечание:** Ограничения CPU могут превышать 1.0, так как это лимиты, а не резервация. Docker будет распределять CPU между контейнерами в зависимости от нагрузки.

## Что можно распараллелить

### Уже реализовано:
1. **Кэширование** - снижает нагрузку на БД и CPU
2. **Rate limiting** - предотвращает перегрузку
3. **Connection pooling** - эффективное использование соединений с БД

### Потенциальные улучшения:

1. **Асинхронная обработка компиляции:**
   - Использовать очередь задач (Redis Queue или RabbitMQ)
   - Обрабатывать компиляции в фоновом режиме
   - Возвращать результат через WebSocket или polling

2. **Batch обработка запросов:**
   - Группировать несколько запросов к БД в один
   - Использовать `@Async` для неблокирующих операций

3. **CDN для статических файлов:**
   - Вынести статические файлы на CDN
   - Снизить нагрузку на Nginx и дисковое пространство

## Мониторинг

### Проверка использования Redis:
```bash
docker exec -it java-course-redis redis-cli
INFO memory
KEYS *
```

### Проверка использования ресурсов:
```bash
docker stats
```

### Проверка кэша:
```bash
# Подключиться к Redis
docker exec -it java-course-redis redis-cli

# Посмотреть все ключи кэша
KEYS cache:*

# Посмотреть TTL ключа
TTL cache:userStatistics:123
```

## Рекомендации

1. **Мониторинг памяти Redis:**
   - Следите за использованием памяти Redis
   - При необходимости уменьшите TTL кэша или увеличьте лимит памяти

2. **Оптимизация кэша:**
   - Анализируйте hit rate кэша
   - Настройте TTL в зависимости от частоты обновления данных

3. **Rate limiting:**
   - При необходимости увеличьте лимит для авторизованных пользователей
   - Настройте разные лимиты для разных эндпоинтов

4. **Масштабирование:**
   - При росте нагрузки рассмотрите возможность увеличения ресурсов
   - Используйте горизонтальное масштабирование backend с Redis для сессий

## Ожидаемые результаты

- **Снижение нагрузки на БД:** до 60-80% за счет кэширования
- **Снижение нагрузки на CPU:** до 40-50% за счет кэширования результатов компиляции
- **Снижение использования памяти:** оптимизированное использование через кэширование
- **Улучшение отзывчивости:** быстрый доступ к кэшированным данным

## Применение изменений

1. Пересоберите backend образ:
```bash
cd backend
docker build -t java-course-backend:latest .
```

2. Обновите docker-compose:
```bash
docker-compose -f docker-compose.prod.yml down
docker-compose -f docker-compose.prod.yml up -d
```

3. Проверьте логи:
```bash
docker-compose -f docker-compose.prod.yml logs -f backend redis
```

4. Проверьте работу кэша:
```bash
# Выполните несколько запросов к API статистики
# Затем проверьте Redis
docker exec -it java-course-redis redis-cli KEYS cache:*
```
