# Устранение проблемы "Connection timed out" при SSH подключении

## Проблема
```
ssh: connect to host 5.129.200.192 port 22: Connection timed out
```

Это означает, что TCP соединение не может быть установлено. Возможные причины:

## 1. Файрвол блокирует порт 22

### Проверка и исправление на сервере:

**Если используется UFW (Ubuntu/Debian):**
```bash
# Проверить статус
sudo ufw status

# Разрешить SSH
sudo ufw allow 22/tcp
sudo ufw allow ssh

# Проверить снова
sudo ufw status
```

**Если используется firewalld (CentOS/RHEL):**
```bash
# Проверить статус
sudo firewall-cmd --list-all

# Разрешить SSH
sudo firewall-cmd --permanent --add-service=ssh
sudo firewall-cmd --permanent --add-port=22/tcp
sudo firewall-cmd --reload

# Проверить
sudo firewall-cmd --list-all
```

**Если используется iptables:**
```bash
# Проверить правила
sudo iptables -L -n | grep 22

# Разрешить SSH (если нужно)
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
sudo iptables-save
```

## 2. SSH сервис не запущен или не слушает на правильном интерфейсе

### Проверка на сервере:

```bash
# Проверить статус SSH
sudo systemctl status sshd
# или
sudo systemctl status ssh

# Если не запущен, запустить:
sudo systemctl start sshd
sudo systemctl enable sshd

# Проверить, на каких интерфейсах слушает SSH
sudo netstat -tlnp | grep sshd
# или
sudo ss -tlnp | grep sshd

# Должно быть что-то вроде:
# tcp  0  0.0.0.0:22  0.0.0.0:*  LISTEN  ...
# Если видите 127.0.0.1:22, значит SSH слушает только на localhost
```

### Проверка конфигурации SSH:

```bash
# Проверить конфигурацию
sudo grep -E "^ListenAddress|^Port" /etc/ssh/sshd_config

# Если нужно изменить, отредактируйте:
sudo nano /etc/ssh/sshd_config

# Убедитесь, что есть:
# Port 22
# ListenAddress 0.0.0.0  (или закомментировано)

# После изменений перезапустите:
sudo systemctl restart sshd
```

## 3. Провайдер/хостинг блокирует входящие соединения

Некоторые провайдеры VPS блокируют входящие соединения по умолчанию. Проверьте:

1. **Панель управления хостингом** - настройки файрвола/безопасности
2. **Security Groups** (если используется облачный провайдер)
3. **Network ACLs** - правила сетевого доступа

### Для популярных провайдеров:

**Timeweb / Selectel / REG.RU:**
- Проверьте раздел "Безопасность" или "Firewall" в панели управления
- Убедитесь, что порт 22 открыт для входящих соединений

**DigitalOcean / AWS / Azure:**
- Проверьте Security Groups / Network Security Groups
- Добавьте правило для порта 22 (TCP) из любого источника (0.0.0.0/0)

## 4. SSH слушает на другом порту

Возможно, SSH настроен на нестандартный порт. Проверьте:

```bash
# На сервере проверьте конфигурацию
sudo grep "^Port" /etc/ssh/sshd_config

# Или проверьте все открытые порты
sudo netstat -tlnp | grep LISTEN
```

Если порт не 22, используйте его в команде:
```bash
ssh -p <ДРУГОЙ_ПОРТ> root@5.129.200.192
```

## 5. Проверка доступности сервера

### С вашего компьютера:

**Windows PowerShell:**
```powershell
# Проверка доступности хоста
Test-NetConnection -ComputerName 5.129.200.192 -Port 22

# Или через telnet (если установлен)
telnet 5.129.200.192 22
```

**Linux/Mac:**
```bash
# Проверка порта
nc -zv 5.129.200.192 22
# или
telnet 5.129.200.192 22
```

## 6. Быстрая диагностика на сервере

Если у вас есть доступ к серверу через панель управления (консоль/веб-SSH), выполните:

```bash
# 1. Проверить статус SSH
sudo systemctl status sshd

# 2. Проверить открытые порты
sudo netstat -tlnp | grep :22
# или
sudo ss -tlnp | grep :22

# 3. Проверить файрвол
sudo ufw status
# или
sudo firewall-cmd --list-all

# 4. Проверить логи SSH
sudo tail -f /var/log/auth.log
# или
sudo journalctl -u sshd -f

# 5. Проверить конфигурацию SSH
sudo sshd -T | grep -E "port|listenaddress"
```

## 7. Временное решение: Использование веб-консоли

Если SSH не работает, используйте веб-консоль в панели управления хостингом для настройки SSH.

## 8. Проверка через панель управления

Если у вас есть доступ к панели управления (как на скриншоте с мониторингом), проверьте:

1. **Раздел "Безопасность"** или **"Firewall"**
2. **Раздел "Сеть"** или **"Network"**
3. **Раздел "SSH"** или **"Доступ"**

Убедитесь, что:
- SSH доступ включен
- Порт 22 открыт для входящих соединений
- Нет блокировок по IP (если есть, добавьте ваш IP или разрешите все)

## 9. Альтернатива: Использование другого порта

Если порт 22 заблокирован провайдером, можно изменить порт SSH:

```bash
# На сервере отредактируйте:
sudo nano /etc/ssh/sshd_config

# Измените:
Port 2222  # или другой свободный порт

# Перезапустите:
sudo systemctl restart sshd

# Обновите файрвол:
sudo ufw allow 2222/tcp

# Подключайтесь:
ssh -p 2222 root@5.129.200.192
```

**Не забудьте обновить `DEPLOY_PORT` в GitHub Secrets!**

## 10. Проверка после исправлений

После внесения изменений проверьте:

```bash
# С вашего компьютера
ssh root@5.129.200.192

# Или с указанием порта
ssh -p 22 root@5.129.200.192
```

## Что делать прямо сейчас

1. **Войдите в панель управления хостингом** (где вы видели мониторинг)
2. **Найдите раздел "Безопасность" или "Firewall"**
3. **Убедитесь, что порт 22 (SSH) открыт для входящих соединений**
4. **Если есть веб-консоль, используйте ее для проверки SSH сервиса:**
   ```bash
   sudo systemctl status sshd
   sudo ufw status
   ```

Если у вас есть доступ к веб-консоли сервера, выполните команды из раздела "Быстрая диагностика" выше.
